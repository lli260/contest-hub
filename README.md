# 🏆 Contest Hub · 比赛查询与备赛管理平台

基于 **Flask + SQLite**，用 `uv` 管理环境。**10 个数据源**并行自动同步最新赛程，
内置 16 场高含金量年度大赛 + 2 个官网入口，支持时间轴导航、五维含金量评级、
参赛计划/任务与笔记、日历导出。

## 快速开始

```bat
cd /d D:\程序\contest-hub

uv sync                 :: 创建/更新虚拟环境并安装依赖
uv run python app.py    :: 启动服务
```

浏览器打开 <http://127.0.0.1:5000>

运行测试：

```bat
uv run pytest                                          :: 离线测试（97 项，不联网；另有 8 项联网测试默认跳过）
set CONTESTHUB_LIVE=1 && uv run pytest tests/test_live.py   :: 联网冒烟测试
```

> 项目已完全改用 `uv` 管理依赖（`pyproject.toml` + `uv.lock`），不再使用 `requirements.txt`。

## 部署

`app.py` 同时导出 WSGI 应用对象 `app`，可直接交由生产级 WSGI 服务器托管：

```python
# app.py
app = create_app()
```

```bat
:: 示例：用 waitress 托管（需先 uv pip install waitress）
uv run waitress-serve --listen 127.0.0.1:5000 app:app
```

数据库默认写在项目根目录的 `contest.db`，可用 `CONTESTHUB_DB` 改到别处
（例如放到数据盘或挂载卷）。


## 本次修复了什么

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| **来源少** | 只有 7 个来源，其中 2 个（牛客/天池）实际上永远抓不到数据 | 新增 **洛谷**、**蓝桥云课** 两个真实可用的数据源（均调官方接口/页面数据）；联网来源增至 7 个 |
| **AtCoder 长期无数据** | 解析正则要求 `</time>` 与 `<a>` 紧邻，真实页面中间隔着大量标签，**一条都匹配不到** | 重写为解析官方 Upcoming 表格；并用 kenkoooo 公开数据补全**原始比赛名** |
| **名称被截断/重复** | `Codeforces Codeforces Round …`、`AtCoder AtCoder …` 重复前缀；AtCoder 名称是空字符串 | 统一 `title_with_brand()` 去重前缀；AtCoder 标题取真实全名 |
| **同一场比赛出现两条** | CF API 同一 id 会同时返回 `BEFORE`（有编号）与 `CODING`（编号被抹掉）两条 | 来源内按 id 去重，优先保留带编号的完整标题 |
| **Kaggle 信息贫乏** | 只有标题，没有奖金、主办方、队伍数、截止日 | 解析奖金池、主办方、参赛队伍数、评测指标、数据方向；**进行中竞赛从 9 条增至 10+ 条** |
| **同步慢** | 串行抓取，一个卡死站点拖住整轮 | 改为**并行 + 硬超时**，整轮同步从数分钟降到 **约 10 秒** |
| **假成功** | 牛客/天池抓不到数据却记成「✅ 成功 0 条」 | 明确报告「该站反爬，无法自动抓取」，同步日志与健康页如实展示 |
| **内置数据不准确** | CCPC「第 11 届总决赛已于 2026-04-25 在南阳理工学院举行」等无依据表述；大量日期是编的 | 重写内置数据：**没把握的日期一律留空**（显示「日期待定」），只标注可确认的；已更正的错误在描述中注明 |
| **脏数据/噪声** | 题库、课程、题解页面会被当成比赛入库；明显错误的年份也会写入 | 新增内容过滤、日期合理性校验；启动时自动修复老库（重复前缀、缺失 source_id、crawl 记录等） |
| **过期比赛一直挂着** | 来源下架的比赛永不消失 | 连续 3 天未再出现 → 自动隐藏（不删除，可在详情页查看） |
| **解析静默失效无人察觉** | 站点改版后解析器常「不报错但只抓到零星几条」 | 新增**覆盖率检测**：低于该来源常规数量时在同步日志与健康页显式告警 |
| **来源归属错乱** | 同步时会把别的来源的记录打上自己的 source_id，并覆盖内置/人工描述 | 只有同来源才能刷新；人工/内置描述永不被机器覆盖；跨来源按「同场次号 + 日期 ±1 天」归并 |

## 更新时效性

- **后台自动同步**：启动后自动同步，默认每 **3 小时**一次。
- **手动同步**：首页一键同步全部/单个来源；采用异步任务，页面不卡住，自动轮询进度。
- **内存缓存**：同一来源抓取结果默认缓存 30 分钟。
- **并发锁**：手动与后台同步互斥，不会并发写库；SQLite 使用 WAL 模式，同步时页面不阻塞。

可用环境变量调整：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CONTESTHUB_SYNC_HOURS` | `3` | 后台同步间隔（小时） |
| `CONTESTHUB_SYNC_DELAY` | `8` | 启动后首次同步延迟（秒） |
| `CONTESTHUB_CACHE_TTL` | `1800` | 抓取缓存时长（秒） |
| `CONTESTHUB_TIMEOUT` | `60` | 整轮抓取硬超时（秒） |
| `CONTESTHUB_PARALLEL` | `6` | 并行抓取并发数 |
| `CONTESTHUB_VANISH_DAYS` | `3` | 来源消失多少天后隐藏 |
| `CONTESTHUB_STALE_DAYS` | `60` | 超过多少天未核实标记「可能过期」 |
| `CONTESTHUB_DISABLE_BG` | - | 设为 `1` 关闭后台自动同步 |
| `CONTESTHUB_DB` | `contest.db` | 数据库路径 |
| `CONTESTHUB_HOST` | `127.0.0.1` | 监听地址 |
| `PORT` | `5000` | 监听端口 |
| `CONTESTHUB_SECRET` | `contest-hub-secret` | Flask session 密钥（生产环境务必修改） |
| `CONTESTHUB_TEST_TMP` | `tests/.tmp` | 测试临时目录 |

完整变量清单见 `.env.example`。所有变量都集中在 `contesthub/config.py` 读取，
新增配置只需在该文件加一行并在 `.env.example` 登记。

## 信息准确性

- **可信度分级**：每张卡片都标出来源与核实状态——`✅ 已人工核实` / `⚠️ 日期待核实` / `🔄 自动同步（含更新时间）`。
- **日期不编造**：内置赛事只有确认过或可推算的日期才填，其余显示「日期待定」并提示以官网为准。
- **精确到分钟**：在线赛展示「10-24 20:00（北京时间，约 1 小时 40 分钟）」，不再只有日期。
- **Kaggle 信息完整**：奖金池、主办方、参赛队伍数、每日/累计提交限制、评测指标、数据方向标签。
- **多级去重**：`source_id` → 归一化 URL → 跨来源「场次号 + 日期 ±1 天」，同一场比赛不会重复入库。
- **字段保护**：人工/内置描述与评分永不被抓取覆盖；赛程日期变化则同步更新。
- **内容过滤**：题库/课程/题解/题目详情页不会作为比赛入库。
- **日期校验**：明显不合理的日期（过早/过晚/结束早于开始）会被丢弃。
- **老库自愈**：启动时自动修复历史脏数据（重复品牌前缀、缺失 `source_id`、过期未隐藏记录）。

## 功能

- 🔍 检索：时间范围、**日期区间**（`from`/`to`）、类别、来源、主办方级别、含金量、状态筛选 + 关键词搜索 + 四种排序
- 📅 时间轴：**年度大赛 / 在线赛分两行**，按日期展示节点（红=顶级），点击跳转
- 🥇 五维含金量评级：主办方级别35% · 获奖难度25% · 政策挂钩15% · 行业认可15% · 历史积淀10%
- 🏷️ 状态标签：报名中 / 即将截止 / 报名已截止·待开赛 / 即将开赛 / 进行中 / **日期待定** / 长期开放 / 已结束
- 🕷️ 多源并行同步 + 数据源健康页 + 数据新鲜度提示 + 过期自动隐藏
- 📆 **日历导出**：`/calendar.ics` 全部，`/calendar.ics?fav=1` 仅收藏（有精确时间时导出为带时区的事件）
- ⭐ 收藏 · 📋 参赛计划与任务清单（带进度）· 📝 笔记（自动生成重点）· ⏰ 14天截止提醒
- ➕ 手动添加任意比赛并录入五维评分

## 目录结构

```
contest-hub\
├── app.py                  # 运行入口 + WSGI 应用对象（uv run python app.py）
├── contest.db              # 数据库（首次运行自动创建并写入内置数据）
├── pyproject.toml          # 项目与依赖声明（uv），含 pytest 配置
├── uv.lock                 # 锁定依赖版本
├── .python-version         # uv 使用的 Python 版本
├── .env.example            # 环境变量模板（复制为 .env 或按需导出）
├── README.md
├── contesthub\             # 应用包（Flask 应用工厂模式）
│   ├── __init__.py         # create_app 工厂
│   ├── config.py           # 路径/同步/缓存/超时配置（均可用环境变量覆盖）
│   ├── db.py               # 建表、增量迁移、老库自愈、WAL
│   ├── seed.py             # 16 场内置赛事 + 2 个精选入口
│   ├── sync.py             # 并行同步、超时、过期隐藏、健康状态
│   ├── util.py             # 日期与自动重点
│   ├── routes.py           # 页面路由 + 同步/状态 JSON API
│   ├── rules\              # 纯逻辑规则层（不依赖 Flask）
│   │   ├── rating.py       # 含金量评级、状态判定、展示字段
│   │   ├── dedup.py        # 归一化、校验、跨来源归并、字段保护
│   │   └── moderation.py   # 非比赛内容过滤
│   ├── sources\            # 可插拔数据源
│   │   ├── base.py         # 基类、HTTP 助手（重试/SSL 回退/编码兜底）
│   │   ├── codeforces.py atcoder.py leetcode.py codechef.py
│   │   ├── luogu.py lanqiao.py kaggle.py moe.py
│   │   ├── nowcoder.py tianchi.py   # 反爬来源：入口 + 可达性检测
│   │   └── __init__.py     # 来源注册表
│   ├── templates\          # index / detail / health 页面（随包分发）
│   └── static\             # 样式与前端脚本（随包分发）
└── tests\                  # 离线 pytest（真实响应片段 fixtures）+ 可选联网测试
    ├── conftest.py         # 公共夹具与自建 TempDir
    ├── fixtures\           # 各来源的真实响应片段
    └── test_*.py
```

在 `contesthub/sources/` 下新增一个文件并在 `__init__.py` 登记即可扩展来源。

## 说明

- 赛程信息来自各平台公开接口与人工整理，**具体以各官网为准**；发现错误可在详情页标记「已核实」。
- 牛客、天池因站点反爬无法自动抓取赛程，保留为官网入口；若你有可用接口，欢迎在 `contesthub/sources/` 里补充。
- 删除 `contest.db` 后重启即可恢复初始内置数据（抓取数据需重新同步）。
- `contest.db` 已加入 `.gitignore`，库文件不会进版本库；克隆后首次启动会自动建库并写入内置数据。
